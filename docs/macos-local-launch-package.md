# macOS 本地 Web 工作台启动包设计

状态：已接受的实施前设计  
范围：macOS 当前芯片架构、本机生成与本机验收  
日期：2026-10-12

交付顺序修订：2026-10-13

## 目标与非目标

第一版交付一个可下载、解压后双击的 Landi 本地启动包。用户无需预装 Node、pnpm、MAH，也无需先完成 Codex、Claude、Telegram 或 Connector 配置，即可启动真实 Landi Server，并在系统浏览器中打开现有 Web 工作台。工作台继续通过既有 Server、Core 和 Storage 使用真实持久化状态；启动包不是示例、静态演示或第二套桌面产品。

本能力不替换 Agent Runtime Adapter，不接入或声称接入 MAH 生成编排，不修改旅行生成、Plan、版本确认或执行权威。它不引入 Electron/Tauri、自动更新、多平台、云部署、对外发布、后台常驻安装或真实旅行操作。历史 MAH 接口可行性报告继续作为未来生成接入限制的证据，但不构成本地工作台启动包的实施门槛。MAH 隔离后台承载是 `mah-background-runtime.md` 定义的另一能力；启动包测试成功或 release readback 成功都不能证明 MAH 已托管实例。

## 唯一规范启动路径

源码只有一个规范启动实现 `scripts/local-launcher.mjs`，打包后位于 `bin/local-launcher.mjs`。Finder 双击入口只把包根和动作传给该实现，不复制进程管理、端口判断、健康检查、浏览器打开或错误恢复逻辑。命令行验收和停止入口也调用同一实现。旧源码 LaunchAgent 工具 `scripts/macos-service.mjs` 及 `service:install:macos`、`service:preview:macos`、`service:remove:macos` 入口全部移除，不保留别名或独立卸载路径。源码 `dev`、`start` 仅供隔离开发，不是面向用户的启动包入口；本次源码清理不卸载、停止、迁移或修改已安装的用户服务及数据。有日期的历史服务审计保留原文，不构成当前启动指导。

规范实现必须使用包内经过固定版本、摘要和架构校验的 Node 官方二进制启动预构建 Server。不得查找或回退到系统 `node`、`pnpm`、开发仓库、全局依赖、MAH 或 Agent CLI。Finder 薄入口定位包根时只使用 shell 内建或 macOS 固定绝对路径的基础工具，不依赖用户 PATH；规范命令入口按真实文件身份识别自身，解压目录的符号链接别名不得造成静默跳过。归档验收首启、重复启动及正常停止必须实际执行包内 `.command` 薄入口，不能只直接调用 Node 绕过该边界。当前打包器固定官方 Node `v25.9.0` 及架构摘要；所携 Node 版本必须满足根 `package.json` 的引擎要求，并通过 `node:sqlite` 加载与最小读写探针；架构必须与第一版包目标一致。前端使用预构建静态资源，运行时只携生产所需依赖，不能把开发 `node_modules` 缓存当作发布依赖。

## 包与用户数据边界

包内容只读且可替换。所有可变状态位于用户目录下的 Landi 专用根目录，并至少分为：

- `config/`：用户可编辑配置和由产品保存的非敏感设置；
- `data/`：SQLite 数据库及其 `-wal`、`-shm` 辅助文件；
- `logs/`：启动器和 Server 日志；
- `run/`：实例锁、进程收据和随机实例令牌等可重建状态。

具体 macOS 根目录采用系统 Application Support/Logs 约定并由规范启动实现唯一解析。Server 通过显式环境变量获得数据库和配置位置，不能读取包目录或源码工作区中的 `.env`、数据库和日志，不能发现或改变已有本机 Landi 服务。升级或重新解压包不会覆盖用户数据；停止和启动失败都不能删除数据。

发布包不得包含 `.env`、真实或测试数据库、SQLite 辅助文件、密钥、令牌、原始对话、附件、日志、MAH Task/Evolution/runtime 记录、源码工作区输出、开发依赖或依赖缓存。必要生产依赖必须由锁文件驱动的干净安装或等价可复核布局产生，并记录清单与摘要。

## 实例、端口与健康所有权

启动器在启动前读取自己的实例收据，但不能仅凭 PID、端口已监听或通用 `/health` 成功认领进程。每次成功启动生成高熵实例令牌；Server 的启动包健康响应必须返回稳定服务身份、协议版本和该实例令牌的安全证明。只有收据、存活 PID、进程启动身份以及健康证明共同匹配，才可判定“本实例已运行”。重复启动复用并聚焦同一实例，不创建第二个 Server。

端口绑定以操作系统结果为最终事实。若目标端口被未知服务占用，启动器必须明确说明端口冲突并退出，不打开浏览器、不杀死、不重启、不请求未知服务的业务数据。不得扫描端口后误接其他 Landi 开发实例。启动器创建的子进程及收据必须关联同一实例令牌；停止操作仅向完全匹配的自有实例发送正常终止信号，并等待退出。身份不完整、PID 被复用或健康证明不匹配时必须拒绝停止并给出安全恢复步骤。

Server 监听成功不等于工作台就绪。已有规范启动器对首启和复用均先验证实例身份，再在 30 秒窗口内等待首页和 `/api/workspace` 全部就绪，才调用 macOS 系统打开命令访问规范本地 URL；重复启动不能因健康证明匹配而跳过工作台就绪检查。复用实例等待失败时，不打开浏览器、不停止原实例、不删除其收据和数据。启动超时、进程提前退出、Node/架构不兼容、数据目录不可写、构建缺失和端口冲突均以简明中文分类提示；详细诊断仅写入专用日志，不向用户显示密钥、内部堆栈或绝对敏感路径。

## 停止与失败恢复

包提供清楚的双击“停止 Landi”入口，该入口只调用规范实现。正常停止等待 Server 的 `SIGTERM` 路径关闭计时器、生成任务、HTTP 服务和 SQLite。若正常停止超时，可只对已再次验证身份的同一 PID 升级终止；不得按进程名或端口批量结束进程。

启动失败后，启动器清理自己创建但未完成的收据和已退出子进程，保留配置、数据库和日志。崩溃遗留收据通过 PID 启动身份与健康证明判定为陈旧后才可替换。恢复提示只允许用户重试、查看本实例日志、停止已确认实例或选择新端口；不得建议删除数据库、编辑内部 MAH 记录、安装开发工具或关闭未知服务。

## 配置与业务边界

页面加载不以 MAH、Agent 登录或 API 配置为前提。现有设置和能力检测继续负责说明缺失配置；生成与外部动作仍遵守现有 Server/Core/Adapter 合同。本启动器不解析旅行需求、不创建 MAH Task、不读写 Generation checkpoint，也不在打开页面前隐式调用 Agent。

## 构建、归档与本机验收合同

本地打包流程必须固定目标架构与官方 Node 版本，验证下载来源、摘要、可执行架构、Node 版本及 `node:sqlite`，然后构建当前提交的前后端和干净生产依赖。归档生成后必须从归档本身解压到隔离目录验收，不能用源码树或宿主开发依赖替代。

### 两阶段交付顺序

为同时保持 MAH 拥有 Git 交付和正式归档必须来自 committed source 两项门禁，本能力按两个顺序阶段交付：

1. 源码交付阶段：在同一 Task 工作树复核启动器、Server、打包、验证 profile、release adapter 及其测试；候选归档可以用于真实边界验收，但必须保存 `sourceState=working_tree`、基线提交和本次变更摘要。该阶段只准备精确的 MAH Git delivery 声明，不将候选归档称为正式发布，不记录运行时切片交付或 T5-1 `ready`。
2. 正式归档阶段：MAH 完成源码提交、推送和远端读回后，从干净组件 HEAD 重新构建归档。正式收据必须保存 `sourceState=committed` 且 `sourceCommit` 等于该 HEAD；随后才执行 provider readback，并用 `verify:local-launch-package -- --output <MAH 管理的发布目录>` 从同一正式归档重跑本节全部验收，再按依赖顺序交付剩余 Evolution 切片和终判。

两阶段之间不得复用候选收据冒充正式 readback，不得把基线提交号描述为本次实现提交，也不得因拆分阶段而降低最终用户验收、归档卫生或实例所有权门禁。第一阶段的签名拒绝和其他失败必须原样保留。

实施阶段至少建立下列自动化和真实边界证据：

1. 构建、类型检查、启动器单元测试和 Server 生命周期测试通过。
2. 在移除 Node、pnpm、MAH 和 Agent CLI 的受控 `PATH` 下，从解压包启动真实服务。
3. 包目录只读、用户目录可写时，首页、实例健康和 `/api/workspace` 均可用；隔离浏览器实际显示现有工作台。
4. MAH 与 Agent 未配置时页面仍能加载，且没有生成或真实外部动作发生。
5. 连续两次启动只保留一个实例；首启和重复启动均在实例身份、首页及工作区 API 全部就绪后才打开页面，复用等待失败时保留原实例及其收据和数据。
6. 未知服务占用端口时明确失败，未知服务保持存活且未被请求为 Landi 工作台。
7. 停止只结束带匹配收据和健康证明的本实例；身份不匹配时拒绝停止。
8. 使用虚构数据写入独立数据库，停止并重启后配置和数据仍存在。
9. 解压包清单和内容扫描证明没有敏感文件、运行记录、日志、数据库、开发依赖或缓存。
10. 记录 macOS 版本、芯片架构、包摘要、Node 版本、源码提交、开始/结束时间、命令退出码和浏览器观察。

MAH 的 `local-launch-package` 验证 profile 是规范验证入口。现有 `landi-local-source` release profile 继续只生成源码归档，不能被描述为启动包。启动包复用已有独立 `landi-local-launch-package` release profile、`scripts/package-macos.mjs` 和 `scripts/local-launch-package-release-adapter.mjs`；adapter 只允许写 Task/MAH 管理的本机发布目录。正式发布仍须满足包摘要、源码提交、目标架构、Node 摘要、验收收据及结构化 readback 的全部门禁；已有实现或 readback 的 `ready` 不能替代真实归档验收。对外发布、部署、签名、公证和自动更新不在本设计范围内。

后台承载适配层若未来实现，也只能调用本节的同一规范启动器，并消费 `docs/contracts/landi-mah-background-runtime.schema.json` 的公开投影。它不能复制端口判断、健康令牌、PID 所有权或停止逻辑。当前 MAH 公共合同缺失时，不得用 `project runtime register`、Project Entry、Schedule、长期 Task 或 LaunchAgent 填补，也不得修改启动器来猜测尚不存在的 MAH 私有协议。
