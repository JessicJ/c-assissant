## 必须保留的产品规则

- 关键信息和冲突在对话中确认后，才显示生成计划卡片。未指定年份时采用今年。
- 普通目的地过夜安排具体酒店；未预订时给出研究过的推荐酒店。次日从前晚酒店出发。明确露营、夜间交通、国际出入境航程适用例外。
- 酒店预订状态不阻止显示建议出发时间；建议时间不能冒充已确认航班或运营商班次。
- 同一地点的卡片、详情、早晚出现使用同一图片资料；缺图有专门查询，单次图片失败不能丢弃已完成行程。
- 国家旅行先考虑特色玩法、区域分配、交通和旅客偏好。不能把入境城市当作全部目的地。
- 保留完整地点目录和已确认预订。纠错可以调整受影响日期的未预订可选活动，不要求错误安排永远原样保留。

## 本轮落实的生成流程

1. 接收已确认事实与完整研究，包括地点坐标、住宿状态、运营事实、官方链接及地点关系。此前这些研究字段没有全部传给日程生成。
2. 保存研究和结构正确的日程检查点；完成日程的检查点按日期与城市签名复用。
3. 统一执行结构、酒店起终点、时间、餐食休息、行李寄存和正式交通节点审查。
4. 独立内容审查路线、节奏及接驳；只使用已有事实，不在此步骤再次全网研究。相同事实与行程的审查结果可缓存14天。
5. 共用最多两轮发布前纠错。一次纠错输出损坏时保留最近有效版本，并把实际失败原因交给剩余轮次。非阻断建议在已有纠错时一并考虑。
6. 缺图按小批次查询并保存成功结果，不能改变路线。最后再次检查完整性并编译草稿。
