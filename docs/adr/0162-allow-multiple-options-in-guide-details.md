# Allow multiple peer options in guide details

Guide detail panels may show multiple concrete options for dining, shopping, and local-experience decisions instead of forcing the Skill to output one best option. This appears as Guide Option Comparison, including Dining Place Comparison, Purchase Place Comparison, and Experience Offering Comparison.

The options should be concrete schedulable objects when they can be added to the itinerary. Web should present them as peer choices and should not label them as candidates or mark one as the default recommended option. Comparison should default to compact Option Comparison Rows or a table-like layout rather than large image-led cards for each option. Comparison can include route fit, distance, price or quality signals, reservation or queue friction, timing, source state, nearby itinerary links, and personal fit.

Web may apply Neutral Option Ordering inside the comparison to reduce browsing effort, such as sorting nearby or lower-friction options first. This ordering must remain factual and non-promotional; it should not create a default winner or visible recommended label.

Forcing a single best option was rejected because dining, shopping, and local experiences often depend on user taste, convenience, budget, and on-the-day conditions. Presenting multiple concrete options as peers makes the workspace more useful for traveler-led itinerary composition without over-intervening.
