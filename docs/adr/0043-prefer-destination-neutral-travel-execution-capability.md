# Prefer destination-neutral Travel Execution Capability

Landi will extend travel execution as a destination-neutral capability rather than creating a Bali-specific product path or another Regional Pack boundary. Bali is the first Validation Scenario because it stresses local mobility, lodging-area choice, weather, food discovery, and external handoffs, but the capability operates from a Destination Execution Context made of current facts and available services.

## Considered Options

- Add a Bali or Indonesia Regional Pack first. This would make the demo concrete quickly, but it would risk hard-coding a single hotspot as the product shape.
- Add a destination-neutral Travel Execution Capability first. This keeps the feature aligned with Landi's broader travel assistant model, while allowing Bali to verify the first implementation.
