# Use capability-driven global source selection

Landi will select travel content sources by needed capability, destination coverage, traveler language, content type, and available connectors rather than by fixed regional source strategies. Region remains a coverage signal, but the architecture starts from needs such as visual inspiration, dining discovery, shopping ideas, maps facts, merchant facts, official verification, and image sourcing.

Hard-coded regional source bundles were rejected because they would make global travel planning broader at first only where a bundle exists, while forcing every new destination into a region taxonomy before Landi can decide which source capabilities are actually needed.
