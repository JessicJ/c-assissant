# Use shared Guide Catalog for planning modules

Landi will model attraction guide, shopping guide, dining guide, and local signature experiences as lenses over one shared Guide Catalog rather than four independent content lists. This preserves cross-module meaning when the same real place or experience belongs to multiple traveler decisions, and lets itinerary promotion, priority changes, archive state, evidence status, and recheck state remain consistent across the Web workspace.

Separate module-specific lists were rejected because they would make the generated plan easier to render at first, but would duplicate travel objects and make user arrangement ambiguous once a traveler adds, removes, or prioritizes an item from one module.
