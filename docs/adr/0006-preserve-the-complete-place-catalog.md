# Preserve the complete Place Catalog

Every valid, distinct place produced for a Trip Blueprint remains in its Place Catalog and remains discoverable in the Web workspace. Scheduling capacity, output length, and current interface visibility must not delete places; unscheduled places remain Candidate Places, while only records confirmed to represent the same real place may be merged.

## Consequences

The Plan Compiler must preserve the Blueprint's Place Catalog after valid deduplication. Automatic merging requires a shared stable external identity, official place identity, or traveler-confirmed alias; name similarity or coordinate proximity only marks a Possible Duplicate and retains both records. Daily itinerary capacity controls scheduling rather than storage. Place Completeness tests compare exact stable-identity sets across Research Set, Trip Blueprint, persistence, and Plan Workspace rendering; equal counts are insufficient.
