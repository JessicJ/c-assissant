# Landi 手机邮件模板

状态：四模板与本地视觉验收。以下保留模板阶段记录；原项目 Skill 中的逐次设计和验收记录已原样移至 [历史邮件设计笔记](history/email-design-notes-2026-10.md)，其中旧许可与通过计数不构成本次授权或验收；当前运行时接入、已实现边界及剩余条件以 `email-execution.md` 为准。

## 参考与范围

2026-10-13 用户提供的 `Landi_四封邮件交互样稿.html` 与 Morning、Transfer、Dining、Change 四张截图是视觉依据。主色 #203E35、正文 #293D34、背景 #FAF8F4。只提供 375、390、430px 手机邮件正文。截图中的邮箱主题、发件人、收件人、手机框与桌面控制台不属于正文。Morning 中误嵌套的八坂神社恢复为独立图文行，不复现该排版缺陷。

四个纯 TypeScript 渲染入口放在 Server 的 `email-templates/` 中，不读取环境、数据库或当前 Plan，不执行外部请求。模板输出完整静态 HTML 文档（包含邮件样式）及独立主题和纯文本。布局采用 presentation table、内联样式与系统字体；媒体查询仅处理窄屏留白与深色增强。无邮件正文 JavaScript、Flex/Grid 布局、交互控件或定位伪元素。

内容由有类型的数据合同传入，结构与视觉由模板持有。计划时刻、交通估算、已确认预约分别使用明确字段或标签。渲染不推断用户位置、完成状态、预约、天气或营业状态。Change 的未应用建议、用户已确认和系统已应用须区分；人工已确认须真实确认时间，系统已应用须持久应用回执、新旧版本、原因与完整新版安排，不得伪造确认时间。分阶段应用和可信消费投影由 email-execution.md 拥有；当前已有 `enqueueAppliedAdjustment` 与显式 `locale=zh-CN` 的 applied 渲染入口，人工确认已通过同请求、真实确认、版本与授权消费投影接线，通知、旧版工作和新版安排分别读回；既有客观应用缺持久公开核验仍拒绝消费，正向渲染只由明确领域 fixture 验证。实际18项视觉与运行验收仍未完成。既有默认和其他三模板保持英语；不重画四模板。退役聊天和历史签名页保持停用。

## 图片与链接

邮件模板只接受 HTTPS 图片地址和 HTTPS 链接，转义所有内容及属性。图片提供 alt、固定展示比例及背景，文字保留关键信息。未来调用方必须提供真实可访问、获准使用的托管 PNG/JPEG 地址。

参考中的内嵌 SVG 插画仅作为授权的开发素材转换成 PNG，存放在 Web `public/email-reference/`。示例数据明确标注示例和待核实，使用保留的 `preview.landi.invalid` HTTPS 资源标识；开发预览在输出后的展示副本中映射至本地 PNG。该映射不属于邮件模板，也不能将演示输出当成可发送邮件。此阶段不上传或发布图片，部署可访问 HTTPS 素材是正式发送前的剩余条件。

## 开发预览

独立 `apps/web/email-preview.html` 使用已有 Vite，独立配置不加载生产 `.env`，不连接 API、不启动 Server/数据库。开发入口切换四种邮件、375/390/430px 宽度、系统/明/暗配色及图片失败演示，控制栏处于正文 iframe 外。Vite 生产构建仍只有原工作台入口，预览模块另有 DEV 守卫。

## 验收

渲染合同检查：HTTPS 地址、HTML 转义、无脚本/事件处理/表单、模板实例隔离、时间与修改状态、文本替代内容。浏览器验收：四封 × 三种宽度、独立邮件截图、与参考逐一观察、长文换行、长名称和链接、所有图片失败、暗色对比与点击区域。Chromium 浏览器验证不等于 Gmail 或 iPhone Apple Mail 实机验证；后者须诚实标为未测试。

本阶段仅交付未接线模板与开发预览，不声明新增生产邮件能力、启用执行工作流或完成 Evolution。MAH 状态查询失败：`MAH Production release identity is not verified`；未写入或伪造 Evolution 状态。生产接入必须另外建立可读回的正式能力合同。

Gmail CSS 依据：https://developers.google.com/workspace/gmail/design/css 。深色增强可能被客户端忽略或被自动反色覆盖，不能以浏览器媒体查询测试代替邮箱测试。

## 本地使用与本次结果

从组件目录执行：

```sh
cd apps/web
pnpm exec vite --config vite.email-preview.config.ts --host 127.0.0.1 --port 5186 --strictPort
```

打开 `http://127.0.0.1:5186/email-preview.html`。可切换四封邮件和三种宽度；`?mail=transfer&bare=1` 等链接提供无控制栏的纯邮件正文。所有点击链接属于普通 HTTPS 跳转，不改变旅行状态。

模板入口：`apps/server/src/email-templates/index.ts` 导出四个 `render*Email(data)` 函数。每个返回 `{ subject, html, text }`。数据类型在 `types.ts`；完整演示数据在 `kyoto-example.ts`。实际调用必须使用业务数据及公开托管图片，不得直接发送开发示例。示例 `sample=false` 但仍携带预览图片标识时，渲染器会拒绝生成。

从组件目录复核：

```sh
pnpm --filter @c-assistant/server exec tsx --test src/email-templates/templates.test.ts
pnpm --filter @c-assistant/server exec tsc --noEmit -p tsconfig.json
pnpm --filter @c-assistant/web typecheck
node scripts/verify-email-preview.mjs output/email-template-verification
```

2026-10-13 本机结果：5 项模板合同测试通过；Server 与 Web 类型检查通过；22 个隔离 Chromium 场景通过，报告及截图在 `output/email-template-verification/`。包含四封邮件 × 375/390/430px（12 项）、四封深色（4 项）、四封真实图片请求失败（4 项）、375px 长餐厅名称换行、开发入口切换与宽度设置。正常状态所有图片加载，邮件按钮实际高度至少 44px；图片失败后文字和链接仍可用，未发生横向滚动。

已逐一查看四封正常截图，并查看图片失败、Transfer 430px、Dining/Change 深色截图，对照用户参考的配色、图片内容、比例、留白、卡片与信息层次。保留原插画，不新增视觉主题。区别：不包含邮箱 UI；Morning 修复参考的图文误嵌套；Dining 每张卡增加原需求要求的计划起点与交通说明；样例价格与估算补充待核实标签；修改状态通过类型分支表达。未执行严格像素差异自动验收，也不声明零差异。

初次浏览器验收在图片失败场景发现嵌套表格被图片固有宽度撑开；统一固定表格布局后复测通过。初次截图保留于 `output/email-template-first-run/`。本机 sandbox 最初阻止 Chromium 启动及 Vite 监听，经执行审批运行隔离浏览器和本机预览后完成验收。

剩余条件：真实 HTTPS 图片尚未发布；真实 Gmail/iCloud 收信与 iPhone Apple Mail 自动反色未验证；无发送、收信、监测、确认交互或生产工作流接入。模板阶段的 MAH 查询当时受 sandbox 限制；后续已通过正式 CLI 读回并建立 T3-2 合同。模板验收不等于运行时或签名交付。

最新邮件编辑要求：四种模板的既有默认正文、标题、alt 与链接名称使用英语。T3-1 持久应用回执交接沿同一 Change 模板显式使用 `locale=zh-CN`，将该路径实际渲染的标题、状态、人工确认／系统应用说明和完整安排固定文案同步为简体中文，HTML 语言标记与纯文本一致；不通过检测汉字自动选择语言，也不改变其他三模板默认值。只复用样稿结构和样式，不套用样稿旅行文案。导语、地点说明及各提示分别限一句简短句子；保留实际 Plan 身份、顺序、时刻和确认事实。Morning 仅把有具体开始时间的安排放到时间轴，无具体时刻的活动另列 At your own pace，删除 Planned 标签；确认预约仍须可辨认。2026-10-14 新版参考要求取代分段短线：时间、连续浅绿细线与活动正文形成三列视觉布局，圆点与线同心且时间与标题对齐；连接线仅存在于首末定时节点之间，不穿透空心节点、不产生首尾尾线。地图保持一个主要按钮，官网来源在其下以简短官方名称的文本链接呈现，不把标题、日期和核实说明塞进按钮。邮件组装前请求 Agent 搜索目的地的官方资料与指定日期天气，返回带来源、日期匹配且简短的英文内容；天气接口缺失时使用已核实的短期官方预报，超出预报期则明确 unavailable，不用当前天气或季节平均冒充当日预报。失败时使用明确未核实的英文保存事实，不虚构状态。需验证英文、时间完整性、未定时隔离、天气日期和来源、移动宽度与长标题，以及真实资料生成。

本轮英文编辑验收：27 项邮件模板、内容、审阅、监测和研究边界测试通过；四模板 22 个隔离手机浏览器场景通过，包含 375/390/430、深色、图片失败与长文本，额外验证了圆点/线中心偏差不超过 1px、无中文及无 Planned 标签。真实指定 Plan 的手册经 Codex 在线研究生成，保留五个计划时刻、未定时活动独立呈现，所有四张图片在浏览器加载成功，三种宽度均无溢出、圆线对齐且无白色来源按钮。日期按英文日历展示，交通摘要与城市标签来自实际路线/地点。未再次发送邮件；真实 Gmail/iPhone Apple Mail 新版显示待用户收信验收。实际手册 HTML 与截图仅保存在被忽略的私有运行数据目录，不进入源码或测试夹具。应用内浏览器拒绝 file 协议导航，未绕过其策略；可查看现有 HTTP 开发模板预览或本机生成的静态截图。
